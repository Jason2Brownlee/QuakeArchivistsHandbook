### **Chapter 8. Search the modern web and search engines**

Teach the learner how to use general-purpose search engines to find surviving references and copies of historical files.

Cover:

- Google.
- Yandex.
- DuckDuckGo.
- Other available search engines.

Explain that different search engines maintain different indexes, so a search that produces no results on Google might produce useful results elsewhere.

Search techniques include:

- Searching the modification name.
- Searching developer names.
- Searching project names.
- Searching every known filename.
- Searching exact filenames using quotation marks.
- Searching distinctive readme content.
- Searching for known historical URLs.
- Searching for known mirrors and distribution locations.

I would emphasise that filename searching becomes particularly valuable later in the research process.

Once you have identified many releases and filenames, you have a much larger collection of search terms to work with.

also, many current websites and file archives are not index by search engines, and indexes may differ across search engines, this is why we check different search engines. many file archives are not indexed, like quake archives on amazon s3 and other cloud providres. many reserrected quake sites are not indexed, like old geocities sites, many sites exclude themselves from the index. so you may find a quake site and have to manually navigate or index it.

Also explain that general search engines are not necessarily good at finding files on old FTP servers or obscure directories.

That leads naturally into the next chapter on ftp archives.

**Outcome:** The learner can systematically search the modern web using information accumulated during earlier research.
